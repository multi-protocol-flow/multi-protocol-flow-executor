# 流程调试器功能需求

**创建时间**: 2026-03-06
**状态**: 待实现
**UI 设计**: [debug-mode-ui-design.md](./debug-mode-ui-design.md)

## 一、功能概述

为流程执行器增加断点调试功能，类似 IDEA 的调试器体验。用户可以在节点上设置断点，执行时在断点处暂停，查看和修改变量，控制执行流程。

## 二、核心功能

### 2.1 断点管理

- **节点级断点**: 点击节点设置/取消断点
- **断点持久化**: 断点作为节点属性保存到流程文件
- **视觉标记**: 有断点的节点显示红色圆点标记

### 2.2 调试控制

| 操作 | 说明 |
|------|------|
| 开始调试 | 从入口节点开始调试执行 |
| 继续 | 执行到下一个断点（无断点则执行到结束） |
| 单步 | 执行当前节点，在下一个节点暂停 |
| 跳过 | 不执行当前节点，直接跳到下一个节点 |
| 执行到底 | 跳过所有后续断点，执行到结束 |
| 结束调试 | 终止调试会话，不生成报告 |

### 2.3 跳过节点的分支处理

#### 条件节点
- 跳过时选择执行分支（true/false）
- 不产生任何输出变量

#### HTTP/WebSocket 节点
- 选择执行分支（默认 out）
- 可选：提供模拟输出（JSON 格式）
- 模拟输出注入到变量池，供后续节点使用

### 2.4 变量管理

- **查看变量**: 暂停时查看所有上下文变量
- **修改变量**: 暂停时可修改变量值
- **变量作用域**: 修改仅当前调试会话生效

### 2.5 执行堆栈

- 查看已执行节点的列表
- 每个节点显示：节点名称、执行时间、输入/输出数据
- 堆栈只读，不可回退

### 2.6 修改节点配置（P1 可选）

- 暂停时可修改节点配置（如 HTTP 节点的 URL）
- 修改仅调试期间生效，不影响原始流程数据
- 调试结束后丢弃所有临时修改

## 三、数据结构变更

### 3.1 Node 类型

新增字段：
- `hasBreakpoint`: 布尔值，标记节点是否设置断点

### 3.2 新增类型

- `DebugSessionState`: 调试会话状态
- `DebugCommand`: 调试命令枚举
- `DebugEvent`: 调试事件枚举
- `DebugStatus`: 调试状态枚举

## 四、断点暂停时机

断点在**节点执行前**暂停：

1. 到达断点节点 → 暂停
2. 用户可查看/修改变量
3. 用户选择操作（继续/单步/跳过）
4. 执行当前节点
5. 进入下一步

## 五、UI 设计

> 详细 UI 设计请参考 [debug-mode-ui-design.md](./debug-mode-ui-design.md)

### 5.1 调试入口

- 位置：画布顶部工具栏
- Debug 按钮：至少设置一个断点后启用
- 点击 Debug → 启动调试会话

### 5.2 调试工具栏

调试模式下替代正常工具栏：

- 继续按钮
- 单步按钮
- 跳过按钮
- 执行到底按钮
- 结束调试按钮

### 5.3 调试面板

位置：画布右侧，替代配置面板

显示内容：
- 当前节点信息
- 上下文变量列表（可编辑）
- 执行堆栈
- 节点输出预览

### 5.4 断点标记

- 位置：节点右上角
- 有断点：红色实心圆点
- 无断点：灰色空心圆点（悬停显示红色）

### 5.5 对话框

**跳过节点对话框**：
- 条件节点：选择分支
- HTTP/WebSocket 节点：选择分支 + 可选模拟输出

**变量编辑对话框**：
- 编辑变量名和值

## 六、技术约束

### 6.1 会话管理

- 同时只能有一个调试会话
- 调试会话期间，正常执行按钮禁用

### 6.2 作用域

- 变量修改：仅调试会话生效
- 节点配置修改：仅调试会话生效
- 断点设置：持久化到流程文件

### 6.3 WebSocket 节点

- 调试时 WebSocket 真实建立连接
- 不进入节点内部，在节点级别暂停

## 八、实施建议

### 8.1 批次执行顺序

严格按照批次编号顺序执行，因为：
- 批次 0 是基础，必须最先完成
- 批次 1-2 可并行（前端/后端独立）
- 批次 3 依赖批次 2
- 批次 4 依赖批次 1 和批次 3
- 批次 5-8 依赖批次 4
- 批次 9 是集成测试，依赖所有功能批次
- 批次 10 是可选增强

### 8.2 验收流程

每个批次完成后，执行以下验收流程：
1. 代码审查（确保符合代码规范）
2. 单元测试通过（覆盖率 > 80%）
3. 功能验收（按验收标准逐项检查）
4. 文档更新（如有必要）

### 8.3 风险提示

| 批次 | 风险 | 应对措施 |
|------|------|----------|
| 批次 3 | 执行器改造复杂度高 | 先实现基础功能，跳过节点功能延后 |
| 批次 7 | 跳过节点的分支选择逻辑复杂 | 充分测试，考虑所有节点类型 |
| 批次 9 | 端到端测试场景多 | 编写自动化测试脚本 |

### 8.4 时间估算

- **核心功能（批次 0-9）**：约 9 天
- **P1 功能（批次 10）**：约 2 天
- **总计**：约 11 天（不含缓冲）

建议预留 20% 缓冲时间，总计约 **13-14 天**。

### 8.5 回归测试

## 九、注意事项

1. 断点作为节点属性，不是流程属性
2. 调试结束后不生成执行报告
3. 修改仅调试期间生效，不影响原始流程
4. 执行堆栈不可回退，只能查看
