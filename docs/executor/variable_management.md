# 变量管理详细设计

**文档位置**：`docs/executor/variable_management.md`
**语言**：中文
**版本**：v2.0

---

## 概述

变量管理系统在节点执行期间传递数据，采用节点隔离设计。每个节点拥有独立的输出空间，确保变量不会互相污染。

---

## VariableStorage 结构

```rust
/// 变量存储（节点隔离）
pub struct VariableStorage {
    /// 全局变量（初始变量 + 显式提升的变量）
    pub global: HashMap<String, serde_json::Value>,
    /// 节点局部变量（node_uuid -> 变量映射）
    pub nodes: HashMap<String, HashMap<String, serde_json::Value>>,
}
```

**字段说明：**
- `global`：全局变量字典，键为变量名，值为 JSON 数据
- `nodes`：节点变量字典，键为节点 UUID，值为该节点的变量字典

---

## 变量类型

### 全局变量

**来源：**
- 初始变量（流程执行前传入）
- 显式提升的变量（节点输出标记为全局）

**特点：**
- 所有节点可直接访问
- 变量名全局唯一
- 生命周期贯穿整个流程执行

### 节点局部变量

**来源：**
- 节点执行输出
- 节点配置产生的中间数据

**特点：**
- 仅存储在对应节点的输出空间
- 需要通过完整访问路径引用
- 生命周期限定在节点执行期间及后续引用

---

## 变量访问路径

| 变量类型 | 访问路径语法 | 示例 |
|---------|-------------|------|
| 全局变量 | `{{variable_name}}` | `{{userId}}` |
| 节点变量 | `{{nodes.{node_uuid}.{key}}}` | `{{nodes.http1.data.user.name}}` |

> **注意**: 当前实现中，变量替换仅支持全局变量。节点局部变量 `nodes.{uuid}.{key}` 访问路径尚未实现。

**路径解析规则：**
1. **全局变量**：直接在 `global` 字典中查找
2. **节点变量**：首先在 `nodes` 字典中查找 `node_uuid`，然后在节点变量字典中查找 `key`
3. 支持嵌套路径（如 `data.user.name`）

```rust
    // 3. 替换为实际值（JSON 字符串）
    // 4. 返回处理后的表达式
}
```

**查找顺序：**
1. 优先查找全局变量
2. 其次查找节点局部变量
3. 变量不存在时返回错误

**类型处理：**
- 简单类型（字符串、数字）：直接替换
- 对象/数组类型：转换为 JSON 字符串
- null 值：替换为 `"null"` 字符串

## 边界情况处理

### 变量不存在
- 返回明确错误信息
- 标识缺失的变量名和访问路径
- 建议检查节点执行顺序

### 类型不匹配
- 优先类型自动转换（如数字转字符串）
- 复杂类型无法转换时返回错误

### 循环引用
- 检测并阻止循环依赖
- 避免无限递归替换
