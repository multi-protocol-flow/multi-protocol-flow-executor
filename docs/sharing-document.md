# Multi-Protocol Flow Executor — 项目分享

## 一、项目背景

### 为什么做这个项目？

在开发和调试涉及 **WebSocket** 的服务时，市面上缺乏一个好用的**可视化多对话编排调试工具**。

典型痛点：

- **Postman / Insomnia** 能发 HTTP 请求，但 WebSocket 只支持单连接、无法编排多轮对话
- **wscat / Postman WebSocket** 只能手动收发消息，无法定义自动化交互流程
- **自动化测试框架**（如 Jest + WebSocket client）需要写代码，调试不直观
- **没有工具能同时调试 WebSocket + HTTP + 数据库 + MCP 等多协议的协同场景**

所以我想做一个：**可视化拖拽编排多协议交互流程，并能在调试过程中实时修改数据的工具**。

### 项目定位

| 维度 | 说明 |
|------|------|
| 形态 | Tauri 2.x 桌面应用 + 独立 CLI 工具 |
| 协议支持 | HTTP、WebSocket、数据库（PostgreSQL/MySQL/SQLite/Redis）、gRPC、MCP、TCP/UDP、MQTT |
| 核心能力 | 可视化流程编排 → 执行 → 调试 → 压力测试 → 报告 |
| 适用场景 | API 联调、WebSocket 多对话调试、多协议集成测试、MCP 工具调试、接口压力测试 |

## 二、核心特性一：WebSocket 多对话编排

### 问题场景

假设你在开发一个**即时通讯后端**，需要验证：

1. 用户 A 连接 WebSocket
2. 用户 B 连接 WebSocket
3. A 发消息 → B 收到消息
4. B 回复 → A 收到回复

传统工具做不到这种**多连接协同编排**。我们的方案是：

### 三种 WebSocket 节点

| 节点 | 功能 |
|------|------|
| **ws_connect** | 建立 WebSocket 连接，可等待初始消息 |
| **ws_send_collect** | 发送消息并等待匹配的响应 |
| **ws_close** | 关闭连接 |

### 连接池 + 所有权移交

**关键设计**：所有 WebSocket 连接放在一个**共享连接池**中。

- `ws_connect` 节点创建连接，放入池子
- 后续的 `ws_send_collect` 节点通过连接 ID 从池子中取连接使用
- 同一个连接可以被**多个节点轮流使用**（所有权移交）
- `ws_close` 节点关闭连接，清理池子

**这意味着**：

- 可以在一条流程中同时管理**多个 WebSocket 连接**（用户 A、用户 B、用户 C……）
- 每个连接的消息收发历史**按节点分段记录**，能清晰看到哪个节点发了什么、收了什么
- 连接支持**消息匹配**（按 JSONPath、正则、表达式匹配特定响应）

### 三种消息收集模式

| 模式 | 说明 |
|------|------|
| **FirstMatch** | 收到第一条匹配的消息就继续（适合 RPC 式请求-响应） |
| **ConditionMatch** | 持续收集直到某条消息满足条件 |
| **DurationCollect** | 收集指定时长内的所有消息（适合观察广播、推送场景） |

### 实际使用示例

**场景：测试聊天服务器的消息转发**

```
[ws_connect: 用户A] ──→ [ws_connect: 用户B] ──→ [ws_send_collect: A发"你好"]
       │                                              │
       │                    ┌─────────────────────────┘
       ▼                    ▼
[ws_send_collect: B等待消息] ──→ [ws_send_collect: B回复"收到"]
                                         │
                                         ▼
                              [ws_send_collect: A等待回复]
                                         │
                                         ▼
                              [ws_close: A] [ws_close: B]
```

每一步的收发消息、匹配结果都能实时看到。

## 三、核心特性二：MCP 协议支持

### 什么是 MCP？

**MCP（Model Context Protocol）** 是一种让 AI 应用与外部工具/资源交互的协议。随着 AI Agent 的流行，越来越多的工具以 MCP Server 的形式提供服务（文件系统、数据库、搜索、代码执行等）。

### 五种 MCP 节点

| 节点 | 功能 |
|------|------|
| **mcp_connect** | 连接 MCP Server，自动发现可用工具、资源、提示词 |
| **mcp_call_tool** | 调用 MCP 工具（带参数） |
| **mcp_read_resource** | 读取 MCP 资源 |
| **mcp_get_prompt** | 获取 MCP 提示词模板 |
| **mcp_close** | 关闭 MCP 连接 |

### 两种传输方式

| 方式 | 说明 | 典型场景 |
|------|------|----------|
| **Streamable HTTP** | 通过 HTTP URL 连接远程 MCP Server | 云端部署的 MCP 服务 |
| **Stdio** | 启动本地子进程作为 MCP Server | `npx @modelcontextprotocol/server-memory` 等本地工具 |

### 工具发现

连接 MCP Server 后，自动列出：

- **工具（Tools）**：可调用的函数，含参数 JSON Schema
- **资源（Resources）**：可读取的数据源
- **提示词（Prompts）**：可获取的提示词模板

在前端配置面板中直接**点选**要调用的工具，参数表单根据 Schema 自动生成。

### 实际使用示例

**场景：调试一个 MCP 文件系统服务**

```
[mcp_connect: 连接文件服务]
         │
         ▼
[mcp_call_tool: 读取文件] ──→ [断言: 确认内容非空]
         │
         ▼
[mcp_call_tool: 写入文件] ──→ [mcp_call_tool: 再次读取] ──→ [断言: 确认内容一致]
         │
         ▼
[mcp_close]
```

### 与 WebSocket 相似的连接池设计

MCP 也使用连接池模式：`mcp_connect` 创建连接 → 下游节点通过连接 ID 引用 → `mcp_close` 关闭。支持在一条流程中连接**多个不同的 MCP Server**，交叉调用。

## 四、核心特性三：调试模式（可修改数据的断点调试）

### 这是最有意思的功能

传统 API 调试工具（Postman 等）是**"发请求 → 看结果"**的模式。如果中间某步返回了意外数据，只能改参数重新来。

我们的调试模式支持**在执行过程中暂停 → 修改数据 → 继续执行**。

### 调试能力一览

| 能力 | 说明 |
|------|------|
| **断点** | 在任意节点上设置断点，执行到该节点时暂停 |
| **单步执行** | 一次执行一个节点，逐步观察 |
| **继续运行** | 从当前位置继续到下一个断点 |
| **跳过节点** | 跳过某个节点不执行，手动指定走哪个分支、注入模拟数据 |
| **运行到结束** | 忽略所有断点，执行完剩余节点 |
| **动态断点** | 调试过程中随时添加/移除断点 |

### 三种"中途改数据"的方式

#### 1. 修改变量（实时生效）

流程执行过程中产生的数据（如 HTTP 响应的 `status`、`body`、`headers`）都以变量形式存在。

调试暂停时，可以直接**修改变量值**：

- 比如接口返回了 `{"code": 500}`，你可以改成 `{"code": 200}`
- 后续节点会使用修改后的值继续执行
- 用来测试"如果接口正常返回，后续流程是否正确"

#### 2. 修改节点配置（仅调试生效）

暂停在某个节点时，可以**临时修改这个节点的配置**：

- 比如改 HTTP 请求的 URL、改 WebSocket 发送的消息内容
- 修改只在当前调试会话中生效，**不会影响原始流程数据**
- 适合测试"如果换一个参数会怎样"

#### 3. 跳过节点 + 注入模拟数据

可以跳过某个节点不执行，并**手动指定它的输出**：

- 比如跳过一个 HTTP 请求节点，手动填入期望的返回数据
- 后续节点基于注入的数据继续执行
- 用来模拟各种返回值场景（成功、失败、边界值），而不需要真实服务

### 调试界面

- **画布**：节点上显示红色断点标记，正在执行的节点高亮
- **调试工具栏**：继续、单步、跳过、运行到结束、结束调试
- **变量面板**：实时显示当前所有变量的值，支持内联编辑
- **执行栈**：显示已经执行过的节点序列和每个节点的结果
- **控制台**：实时输出执行日志

### 实际使用场景

**场景：调试一个需要 Token 的接口调用链**

```
[HTTP: 登录获取Token]  ← 正常执行，返回 token
         │
         ▼
[HTTP: 查询用户信息]   ← 在这里暂停，Token 自动传递
         │                修改变量：把 token 改成过期的
         ▼
[HTTP: 刷新Token]     ← 继续执行，验证刷新逻辑是否正确
         │
         ▼
[HTTP: 重新查询]       ← 使用新 Token 继续查询
```

全程不需要改代码、不需要重新登录，**在调试过程中直接修改数据**，快速验证各种场景。

## 五、CLI 工具：命令行下的流程执行

### 为什么需要 CLI？

- **CI/CD 集成**：自动化测试流水线中执行流程
- **批量验证**：快速验证一批接口是否正常
- **压力测试**：从服务器环境发起压力测试
- **AI Agent 集成**：用 JSON 协议交互，方便程序调用

### 六个子命令

| 命令 | 说明 |
|------|------|
| `mpe run` | 执行流程文件，支持实时流式输出 |
| `mpe validate` | 验证流程文件是否正确 |
| `mpe debug` | 交互式调试（通过 stdin/stdout 的 JSON 协议） |
| `mpe stress` | 压力测试（并发用户、渐进启动、百分位报告） |
| `mpe flow` | 管理流程文件（列表、查看、创建、编辑、导入） |
| `mpe report` | 管理执行报告（列表、查看、删除） |

### 与桌面应用共享引擎

CLI 和桌面 GUI 使用**完全相同的执行引擎**，零重复逻辑。在 GUI 上编排好的流程，可以直接用 CLI 执行。

### 特色功能

#### 流式输出

```bash
mpe run -f flow.mpf --stream
```

执行过程中实时输出每个节点的执行结果（NDJSON 格式，每行一个 JSON），方便对接监控或日志系统。

#### CLI 调试

```bash
mpe debug -f flow.mpf --break node-uuid-1 node-uuid-2
```

通过 stdin/stdout 进行交互式调试：

- stdout 输出调试事件（暂停、节点执行完成等）
- stdin 接收调试命令（继续、单步、修改变量等）

**这个设计特别适合 AI Agent 调用** —— 机器可读的 JSON 协议，不需要 GUI。

#### 程序化编辑流程

```bash
mpe flow edit node-add --type http --name "新请求"
mpe flow edit connection-add --source node-1 --target node-2
mpe flow edit variable-set --name token --value "abc123"
```

完全通过命令行构建流程，无需打开 GUI。适合 CI/CD 或脚本化场景。

#### 压力测试

```bash
mpe stress run -f flow.mpf -c 100 -d 60 -o report.json
```

| 参数 | 说明 |
|------|------|
| `-c 100` | 100 个并发虚拟用户 |
| `-d 60` | 持续 60 秒 |
| `-o report.json` | 输出报告 |

报告包含：p50/p90/p95/p99 延迟分布、成功率、RPS、每个节点的独立延迟统计。

## 六、其它亮点

### 多协议统一编排

一条流程中可以混合使用多种协议：

```
[HTTP: 获取配置] → [DB: 查询数据] → [gRPC: 调用后端服务] → [WebSocket: 推送结果]
```

所有协议共享同一套变量系统，上游节点的输出自动作为下游节点的输入。

### 变量模板

所有节点的配置字段都支持 `{{variable_name}}` 模板语法：

- `{{url}}` → 从变量中取值
- `{{body.token}}` → 支持 JSONPath 取嵌套值
- 可以在脚本节点中用 JS 自由处理变量

### 断言节点

15 种断言操作符（等于、不等于、大于、包含、正则匹配、存在、范围等），支持 All/Any 组合模式。断言失败走 false 分支，不阻断整条流程。

### 脚本节点

内嵌 JavaScript 运行时，可以在流程中写 JS 脚本处理数据：

```javascript
// 从上游 HTTP 响应中提取 Token
const body = fn.response.body;
const token = body.data.token;
fn.variables.set("token", token);

// 条件控制
if (body.code !== 200) {
    fn.flow.abort("接口返回错误");
}
```

### CSV 数据集驱动

上传 CSV 文件，每一行作为一组参数执行一次流程。适合：
- 参数化测试（多组输入验证）
- 数据迁移验证
- 批量操作

### 加密存储

数据库密码等敏感信息使用 **AES-256-GCM 加密**存储，密钥存在操作系统的密钥链中（Windows 凭据管理器 / macOS Keychain / Linux Secret Service），配置文件中不会出现明文密码。

## 七、总结

| 维度 | 我们做的 |
|------|----------|
| **WebSocket** | 多连接共享池 + 所有权移交 + 消息匹配 + 多轮对话编排 |
| **MCP** | 工具/资源/提示词 全链路支持 + 自动发现 + 双传输模式 |
| **调试** | 断点 + 单步 + 中途修改变量/配置 + 跳过注入模拟数据 |
| **CLI** | 与 GUI 共享引擎 + 流式输出 + 交互式调试 + 压力测试 |
| **多协议** | 13 种协议统一编排，共享变量系统 |
| **扩展性** | 新增协议只需实现插件接口并注册 |

**核心价值**：一个工具覆盖 API 调试 → 多协议编排 → 可修改数据的断点调试 → 压力测试的完整链路。
